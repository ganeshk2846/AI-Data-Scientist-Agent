## 1. Executive Summary & Architectural Paradigm

The **AI for BI — Domain-Independent AI Data Scientist Agent** is an enterprise-grade conversational business intelligence and automated data science platform. It bridges the gap between natural language business inquiries and rigorous, deterministic relational database analytics.

### Core Architectural Invariants

1. **One User $\rightarrow$ One Active Database Connection $\rightarrow$ One Engine at a Time:**
   The backend enforces a strict single-active-database lifecycle via `DatabaseConnectionManager`, preventing connection state corruption and ensuring unambiguous query routing.
2. **Zero Schema Hallucination via Grounded Hybrid Retrieval:**
   Every generated SQL query is strictly constrained to introspected table and column identifiers discovered dynamically through Reciprocal Rank Fusion (RRF) combining persistent BM25 lexical precision, LanceDB dense vector embeddings (FastEmbed ONNX), and foreign-key graph traversal.
3. **Four-Tier Defense-in-Depth Read-Only Fortress:**
   User database immutability is guaranteed without relying on speculative or destructive write probes. The platform layers:
   - Driver URI read-only modes (`mode=ro`).
   - Session PRAGMAs (`PRAGMA query_only = ON`) and transaction modes.
   - Dialect AST parsing (`sqlglot`) disallowing DDL/DML.
   - Row bounding injection (`LIMIT 1000`) and execution timeout enforcement.
4. **Deterministic Analytical Computation (No LLM Math):**
   Calculations, aggregations, anomaly detection, time-series forecasting, and constrained resource optimizations are performed entirely by deterministic Python scientific libraries (`scipy`, `sklearn`, `statsmodels`, `lightgbm`, `pandas`, `numpy`). The LLM is restricted to semantic routing, query translation, and narrative synthesis.
5. **Factual Faithfulness & Causal Guardrails (The Critic):**
   Narratives and recommendations generated by the system are cross-examined against ground-truth computed metrics using regex validation. Unhedged causal statements (e.g., claiming "proven root cause" from observational data) are intercepted and penalized with confidence discounts.
6. **Executive Management Support:**
   Complex business questions decompose into a 1-to-4 stage Directed Acyclic Graph (DAG) covering **WHAT** (Descriptive), **WHY** (Diagnostic), **WHAT NEXT** (Predictive), and **SO WHAT** (Prescriptive), presented via structured executive decision cards.

## 4. Backend API Gateway & Transport Layer

The backend is built with FastAPI and runs on Python 3.11+.

### Entry Point & Middleware (`backend/app/main.py`)

- **`RequestIdMiddleware`:** Injects a unique `X-Request-ID` (UUID4) into every request state and headers, recording execution duration in `X-Process-Time-Ms`.
- **`CORSMiddleware`:** Permits frontend origins (`http://localhost:3000`, `http://localhost:3001`, `http://localhost:3002`) and matches regex localhost ports while rejecting open wildcard access.
- **`lifespan` Context Manager:**
  1. Bootstraps `DatabaseConnectionManager`.
  2. Verifies readiness and immutability of the active database.
  3. Checks LLM provider configuration (`ollama`, `gemini`, `openai`, or `mock`).
- **Standardized Exception Handlers:** Wraps application exceptions, validation errors, and HTTP failures in uniform JSON responses conforming to `APIResponse[T]`.

## 5. Autonomous Multi-Agent Orchestration & Specialist Subsystem

Phase 5 unifies the analytical capabilities into a collaborative multi-agent architecture.

### Central Supervisor Agent (`backend/app/orchestration/supervisor.py`)

The `AgenticSupervisor` orchestrates high-level business questions through a multi-stage lifecycle:

1. **Security & Injection Interception:**
   Evaluates user input against `detect_prompt_injection()` and regex patterns for destructive SQL/DDL (`DROP`, `DELETE`, `UPDATE`, `INSERT`, `ALTER`, `TRUNCATE`, `PRAGMA`). If detected, execution halts immediately with a failed security task.
2. **Database-Isolated Session Context:**
   Conversational context is strictly isolated by compound key `(session_id, db_fingerprint)`. If the active database switches, prior context is automatically invalidated to guarantee zero cross-database leakage.
3. **Multi-Stage Analytical Planning:**
   Coordinates with `IntentClassifier` to identify whether a query is single-intent or composite (e.g., 2-stage, 3-stage, or 4-stage).
   - Natural execution sequence: $\text{DESCRIPTIVE} \rightarrow \text{DIAGNOSTIC} \rightarrow \text{PREDICTIVE} \rightarrow \text{PRESCRIPTIVE}$.
4. **Task DAG Formulation:**
   Builds a structured list of `AgentTask` instances:
   - `Task 1`: `DATA_RETRIEVAL` (Schema-grounded SQL query and DataFrame extraction).
   - `Tasks 2..K`: Analytical stages assigned to specialist roles.
   - `Final Task`: `CRITIC` (Faithfulness validation and claim cross-examination).
5. **Sequential Execution & Data Passing:**
   Executes tasks sequentially. The extracted `pandas.DataFrame`, computed metrics, and executed SQL statements pass seamlessly from stage to stage.
6. **Graceful Failure & Safe Abstention:**
   If a specialist cannot defensibly proceed (e.g., fewer than 6 temporal points for forecasting, or missing optimization variables), it emits a structured abstention. Preceding successful stages are retained without crashing the pipeline.
7. **Executive Management Synthesis:**
   Aggregates findings into the structured `ManagementResponse` containing WHAT, WHY, WHAT NEXT, and SO WHAT sections strictly corresponding to executed stages.

### The 5 Specialist Analytical Agents (`backend/app/orchestration/specialists.py`)

1. **`DataRetrievalSpecialist` (`DATA_RETRIEVAL`):**
   - Coordinates schema discovery, minimal SELECT formulation, AST validation, and read-only database execution.
   - Outputs extracted DataFrame and query provenance.
2. **`DiagnosticSpecialist` (`DIAGNOSTIC`):**
   - Executes period-over-period variance decomposition, driver ranking, and Isolation Forest anomaly detection.
   - Injects mandatory non-causal disclaimer: *"Statistical Note: Identified relationships reflect empirical observational correlation and variance decomposition. They do not imply verified counterfactual causality."*
3. **`PredictiveSpecialist` (`PREDICTIVE`):**
   - Conducts multi-model forecasting tournaments (LightGBM vs. ARIMA) and computes 80% & 95% prediction intervals.
   - Enforces temporal minimum check ($\ge 6$ historical observations); defensively abstains when historical depth is insufficient.
4. **`PrescriptiveSpecialist` (`PRESCRIPTIVE`):**
   - Formulates SciPy SLSQP constrained optimization based on empirical data aggregations and budget constraints.
   - Attaches mandatory advisory disclaimer: *"Advisory Note: Prescriptive outputs represent mathematical decision-support models. The system does not autonomously execute financial or operational business transactions."*
5. **`CriticSpecialist` (`CRITIC`):**
   - Cross-examines narrative statements against ground-truth metrics computed by Python engines.
   - Checks quantitative values, percentage changes, monetary figures, and directional deltas.
   - Intercepts unhedged causal claims (e.g., "proven root cause") and applies confidence score discounts.

## 6. Schema-Grounded Data Retrieval & Persistent Hybrid RAG Pipeline

The retrieval subsystem grounds queries strictly in the active database schema without hallucination.

```
[ Natural Language Business Question ]
                 │
   ┌─────────────┴─────────────┐
   ▼                           ▼
[ Lexical BM25 ]        [ Dense FastEmbed ]
(Persistent Index)     (BAAI/bge-small-en-v1.5)
   │                           │
   │  BM25 Rank & Score        │  Dense Cosine Similarity
   └─────────────┬─────────────┘
                 ▼
[ Reciprocal Rank Fusion (RRF k=60) ]
Score = 1/(60 + b_rank) + 1/(60 + e_rank)
                 │
                 ▼
[ 1-Hop Foreign Key Graph Expansion ]
(Discovers related fact/dimension join targets)
                 │
                 ▼
[ Value Linker & Semantic Layer ]
(Maps colloquial tokens to verified DB literals)
                 │
                 ▼
[ Minimal Prompt Schema Context ]
```

### Components (`backend/app/retrieval/`)

1. **`HybridSchemaRetriever` (`hybrid.py`):**
   Coordinates lexical and dense retrieval using Reciprocal Rank Fusion with standard constant $k = 60$. Expands retrieved tables via 1-hop foreign key traversal to ensure join paths are present in schema prompts.
2. **`PersistentBM25Retriever` (`persistent_bm25.py`):**
   Tokenizes table names, column profiles, and domain descriptions. Stores inverted index on disk at `data/bm25/{fingerprint}/`.
3. **`LanceDBVectorStore` (`vector_store.py`):**
   Persistent on-disk vector database storing dense embeddings of database tables and metadata at `data/lancedb/{fingerprint}/`.
4. **`FastEmbedProvider` (`embeddings.py`):**
   Local ONNX dense embedding generator using `BAAI/bge-small-en-v1.5`. Runs 100% locally with zero external network overhead.
5. **`ValueLinker` (`value_linker.py`):**
   Maps colloquial user tokens to exact database categorical literals (e.g., matching `"vip"` to `customer_segments.segment_name = 'VIP'`). Discovers low-cardinality categories ($\le 50$ distinct values) dynamically from the active schema catalog.
6. **`DynamicSemanticEngine` (`semantics.py`):**
   Maintains domain-independent business metric definitions, calculating introspected aggregations (e.g., Gross Revenue, Delivered Order Count).

## 7. Deterministic Analytical & Machine Learning Engines

Deterministic computation occurs within specialized engines:

### 1. Descriptive Analytics Engine (`backend/app/analysis/descriptive_engine.py`)
- Calculates summary statistics (mean, median, standard deviation, IQR, percentiles 25/75/90/95).
- Period-over-period delta computations with directional labels (`INCREASE`, `DECREASE`, `STABLE`).
- Trend decomposition across temporal event series.

### 2. Diagnostic Analytics Engine (`backend/app/analysis/diagnostic_engine.py`)
- **Anomaly Detection:** Multi-algorithm evaluation using Scikit-Learn `IsolationForest` (contamination 0.05) and robust Median Absolute Deviation (MAD) Z-Score ($|z| > 2.5$).
- **Driver Ranking & Variance Decomposition:** Evaluates categorical subgroup contributions to aggregate variance changes.
- **Statistical Testing:** Welch's t-test and Mann-Whitney U test with p-value reporting.

### 3. Predictive Analytics Engine (`backend/app/analysis/predictive_engine.py`)
- **Forecasting Tournament:** Backtests multiple candidate models on historical time-series:
  - Naive & Seasonal Naive.
  - Exponential Smoothing (Holt-Winters).
  - Statsmodels `ARIMA(p, d, q)`.
  - LightGBM Regressor (`LGBMRegressor`) with autoregressive lag features.
- **Evaluation:** Scores out-of-sample performance using Symmetric Mean Absolute Percentage Error (sMAPE), MAE, and RMSE.
- **Uncertainty Bounds:** Derives 80% and 95% prediction intervals from empirical residual distributions.
- **Defensive Guardrail:** Requires at least 6 historical time points; abstains gracefully if temporal history is insufficient.

### 4. Prescriptive Analytics Engine (`backend/app/analysis/prescriptive_engine.py`)
- **Constrained Optimization:** Formulates resource allocation problems solved via SciPy `optimize.minimize` (SLSQP) or `optimize.linprog`.
- **Grounded Categorical Efficiencies:** Dynamically calculates ROI/efficiency coefficients from actual grouped data aggregations (`df.groupby(cat)[target].mean()`).
- **DEF-01 Currency Budget Parsing:** Regex with negative lookahead assertion `r"\$\s*(\d+(?:,\d{3})*(?:\.\d+)?)\s*(k|m|b)?(?![a-zA-Z])"` prevents natural words like "marketing" or "month" from triggering unit scaling.
- **Diagnostics:** Emits Kuhn-Tucker optimality verification, solver status, constraint violation checks, and sensitivity coefficients.

### 5. Faithfulness Validator (`backend/app/analysis/faithfulness.py`)
- Scans narrative text for numerical values, percentages, dollar amounts, and directional claims.
- Validates each extracted claim against ground-truth metric values with relative tolerance ($\le 5\%$).
- Intercepts unhedged causal phrases (`"proven root cause"`, `"direct causal effect"`), flagging them as non-causal discrepancies and discounting overall confidence.

## 8. Multi-Engine Database Abstraction & 4-Tier Read-Only Safety Fortress

The database abstraction layer isolates the application from engine-specific dialect nuances while enforcing absolute read-only immutability.

### Database Connection Manager (`backend/app/db/manager.py`)
- Maintains a single active adapter conforming to `BaseDatabaseAdapter`.
- Persists active connection configurations with symmetric encryption (`AES-256` via `Fernet`) in `agent_app.sqlite`.
- Seeds baseline SQLite warehouse (`ecommerce.db`) automatically if present.

### Four-Tier Read-Only Safety Architecture

```
[ User Natural Language Query ]
               │
               ▼
┌────────────────────────────────────────────────────────┐
│ TIER 3: AST & Keyword Guardrail (sqlglot)              │
│ Parses AST; permits only Select/Union; blocks DDL/DML; │
│ rejects PRAGMA, ATTACH, COPY, VACUUM, LOAD_EXTENSION.  │
└──────────────────────────────┬─────────────────────────┘
                               │
                               ▼
┌────────────────────────────────────────────────────────┐
│ TIER 4: Row Bounding & Timeout Guardrail               │
│ Automatically injects LIMIT 1000; enforces 30s timeout. │
└──────────────────────────────┬─────────────────────────┘
                               │
                               ▼
┌────────────────────────────────────────────────────────┐
│ TIER 2: Engine Session Read-Only Hook                  │
│ SQLite:     PRAGMA query_only = ON;                    │
│ PostgreSQL: SET default_transaction_read_only = ON;    │
│ MySQL:      SET SESSION TRANSACTION READ ONLY;         │
└──────────────────────────────┬─────────────────────────┘
                               │
                               ▼
┌────────────────────────────────────────────────────────┐
│ TIER 1: Driver URI & OS-Level Read-Only Mode           │
│ SQLite:     file:path.db?mode=ro                       │
│ PostgreSQL: Connection read_only parameter             │
│ MySQL:      Read-only connection configuration         │
└──────────────────────────────┬─────────────────────────┘
                               │
                               ▼
               [ Physical Database Warehouse ]
```

## 9. LLM Provider Integration & Inference Gateway

The LLM abstraction (`backend/app/llm/`) standardizes model interactions via `BaseLLMProvider`.

### Supported Providers (`backend/app/llm/client.py`)

1. **`OllamaLLMProvider` (`backend/app/llm/ollama_client.py`):**
   - Primary default local inference provider.
   - Communicates asynchronously via HTTP with local Ollama daemon (`http://localhost:11434`).
   - Default model: `qwen3:4b`.
   - Zero cloud API dependency, zero external token cost.
2. **`GeminiProvider` (`backend/app/llm/client.py`):**
   - Cloud provider using the official `google-genai` SDK.
   - Default model: `gemini-3.5-flash-lite`.
   - High-speed, sub-second executive synthesis with graceful fallback to grounded mock on network exceptions.
3. **`OpenAIProvider` (`backend/app/llm/client.py`):**
   - Cloud provider using the `openai` SDK (`gpt-4o-mini`).
4. **`MockLLMProvider` (`backend/app/llm/client.py`):**
   - Deterministic, schema-grounded mock provider for automated unit testing and offline development.
   - Generates verified SQL matching `ecommerce.db` tables.

*Note on Anthropic:* Configuration keys (`ANTHROPIC_API_KEY`) exist in `Settings`, but an active Anthropic client class is not implemented in `client.py` (falls back to Ollama).

## 10. Observability, Telemetry & Session Memory

### Observability Tracer (`backend/app/observability/tracer.py`)
- Records individual execution traces in `agent_app.sqlite` (`ops_run_traces` table).
- Tracks `run_id`, `session_id`, `query`, `intent`, `latency_ms`, `sql_executed`, `row_count`, `cost_estimate_usd`, and `verification_status`.
- Computes aggregate telemetry: p50, p95, and p99 latency percentiles, success rate, and safety block tallies.

### Shared Memory Service (`backend/app/memory/service.py`)
- Manages multi-turn conversation threads.
- Isolates sessions and resolves conversational follow-ups through standalone question rewriting rather than crude text concatenation.
