## 1. Natural Language Query Processing Lifecycle

The pipeline processes user questions through 11 distinct stages in [`backend/app/workflow/orchestrator.py`](file:///c:/D_drive/AI_FOR_BI_P/backend/app/workflow/orchestrator.py):

```
User Query
    │
[Stage 1: Prompt Injection Guardrail] ──► (Blocked if adversarial pattern detected)
    │
[Stage 2: Context Resolution & Memory] ──► (Rewrites follow-up using active frame)
    │
[Stage 3: Answerability Fast-Path Gate] ──► (Refuses unsupported domains or dates)
    │

    │
[Stage 5: Hybrid Schema Grounding & Value Linking] ──► (BM25 + TF-IDF RRF + FK Graph)
    │

    │
[Stage 7: AST Validation & Schema Conformance] ──► (sqlglot checks, table allowlist)
    │ (If invalid)
    ├─► [Bounded SQL Repair Loop: Max 2 Attempts]
    │
[Stage 8: Read-Only Query Execution] ──► (sqlite3 URI mode=ro, 30s timeout)
    │ (If execution error)
    ├─► [Bounded Execution Repair Loop: Max 2 Attempts]

    │

    │

## 2. Text-to-SQL Prompt Construction

The SQL generation prompt is constructed dynamically in [`backend/app/workflow/orchestrator.py#L42-L58`](file:///c:/D_drive/AI_FOR_BI_P/backend/app/workflow/orchestrator.py#L42-L58):

```python
SQL_GEN_PROMPT = """You are an expert Data Scientist and SQL Engineer specializing in SQLite.
Write a single, safe, read-only SQLite SELECT query to answer the user's business question.

STRICT CONSTRAINTS:
1. Use ONLY the table and column identifiers provided in the schema context below.
2. NEVER invent column names or table names.
3. Use SQLite functions (e.g. strftime, ROUND, COUNT, SUM, AVG).
4. For revenue or money values, ROUND(..., 2).
5. Output ONLY the raw SQL inside a markdown ```sql code block. No extra conversation.

SCHEMA CONTEXT:
{schema_context}

{linked_values_context}

{metrics_context}
"""
```

### Context Sections Injected:
1. **`schema_context`:** Generated by [`DatabaseCatalog.to_minimal_prompt_schema()`](file:///c:/D_drive/AI_FOR_BI_P/backend/app/schema/models.py#L75-L94). Formats retrieved tables with column names, data types, `[PK]` flags, and `[FK -> table.column]` links. Excludes raw data rows to conserve tokens and prevent data leakage.
2. **`linked_values_context`:** Injects literal recommendations from `ValueLinker` (e.g. `Entity 'delivered' matches column orders.order_status = 'delivered'`).
3. **`metrics_context`:** Injects formulas from `CANONICAL_METRICS` (e.g. `Gross Revenue: Formula: ROUND(SUM(total_amount), 2)`).

## 3. SQL Validation and Security Guardrails

Security and safety are enforced by a two-tier guardrail system: AST validation before execution, and operating-system-level read-only URI enforcement during execution.

### 3.1 AST Parsing and Prohibited Expressions (`SQLValidator`)
Implemented in [`backend/app/sql/validator.py`](file:///c:/D_drive/AI_FOR_BI_P/backend/app/sql/validator.py):
- **AST Parser:** Uses `sqlglot.parse_one(cleaned_sql, read="sqlite")`.
- **Statement Count Check:** Splits on unescaped semicolons; strictly rejects multi-statement chaining.
- **Top-Level AST Type:** Must be an instance of `sqlglot.exp.Select` or `sqlglot.exp.Union`. Rejects `Insert`, `Update`, `Delete`, `Create`, `Drop`, `Alter`.
- **Prohibited Sub-Expressions:** Scans AST for forbidden expressions inside subqueries or CTEs:
  `exp.Insert`, `exp.Update`, `exp.Delete`, `exp.Create`, `exp.Drop`, `exp.Alter`, `exp.Command`, `exp.Pragma`.
- **Prohibited SQLite Commands:** Keyword search blocks `ATTACH`, `DETACH`, `PRAGMA`, `LOAD_EXTENSION`, `VACUUM`, `REINDEX`.
- **Prohibited Functions:** Blocks `WRITEFILE`, `READFILE`, `EDIT`, `SHELL`.

### 3.2 Schema Identifier Conformance Check
- The validator extracts all table identifiers referenced in the query:
  `referenced_tables = [t.name.lower() for t in expression.find_all(exp.Table)]`
- Verifies every referenced table against `catalog.tables.keys()`.
- CTE aliases (e.g. `WITH monthly_rev AS (...)`) are extracted and excluded from catalog checks.
- If an uncataloged table is referenced, validation fails with:
  `"Schema validation error: Table '<name>' does not exist in the connected database."`
- **Limitation Discovered:** Column identifiers are **not** currently validated against column lists in the AST; only table names are strictly checked against the catalog.

### 3.3 Row Limits and Cost Guards
- **Row Limit Enforcement:**
  - If query has no `LIMIT` clause, `expression = expression.limit(settings.SQL_MAX_ROWS_RETURN)` automatically injects `LIMIT 1000`.
  - If user query specifies a limit exceeding 1,000, it is capped down to 1,000.
- **Cartesian Cross-Join Cost Guard:** [`backend/app/security/guardrails.py#L96-L98`](file:///c:/D_drive/AI_FOR_BI_P/backend/app/security/guardrails.py#L96-L98) checks AST `exp.Join` nodes. If a `CROSS` join is declared without an `ON` condition, it is rejected to prevent out-of-memory or high CPU lockup.

## 4. Bounded SQL Repair Loop

Implemented in [`backend/app/sql/repair.py`](file:///c:/D_drive/AI_FOR_BI_P/backend/app/sql/repair.py#L36-L91):
- **Bound:** Capped strictly at a maximum of **2 repair attempts**.
- **Trigger Points:**
  1. **Validation Failure:** If `sql_validator` fails (e.g. invalid syntax, uncataloged table, forbidden token).
  2. **Execution Failure:** If `sqlite3` execution raises an `OperationalError` (e.g. ambiguous column name, type mismatch, missing column).
- **Repair Cycle:**
  1. Sends failing SQL, exact error message, user query, and minimal schema prompt to LLM via [`REPAIR_SYSTEM_PROMPT`](file:///c:/D_drive/AI_FOR_BI_P/backend/app/sql/repair.py#L16-L33).
  2. Receives candidate corrected SQL.
  3. Re-validates candidate SQL through `sql_validator.validate_and_format_sql()` from scratch.
  4. If validation passes, updates `sanitized_sql` and resumes execution.
  5. If validation fails and attempt < 2, retries. If attempt reaches 2, terminates and returns a structured refusal message with error explanations.

## 5. Query Execution and Verification

### 5.1 SQLExecutor Execution
Implemented in [`backend/app/sql/executor.py`](file:///c:/D_drive/AI_FOR_BI_P/backend/app/sql/executor.py):
- Opens connection via [`get_readonly_connection()`](file:///c:/D_drive/AI_FOR_BI_P/backend/app/db/connection.py#L24) (`mode=ro`).
- Sets query timeout (`timeout=30.0`).
- Fetches rows via `cursor.fetchmany(1001)`.
- If 1001 rows returned, marks `truncated = True` and trims to 1000.
- Calculates elapsed execution time in milliseconds using `time.perf_counter()`.
- Formats rows as list of dictionaries using `cursor.description` column names.

### 5.2 Verification & Bounds Checking
Implemented in [`backend/app/workflow/orchestrator.py#L455-L480`](file:///c:/D_drive/AI_FOR_BI_P/backend/app/workflow/orchestrator.py#L455-L480):
- Evaluates [`VerificationResult`](file:///c:/D_drive/AI_FOR_BI_P/backend/app/workflow/models.py#L34):
  - Checks if result set contains 0 rows (`empty_result = True`).
  - Checks if result set was capped at row bounds (`truncated = True`).
  - Appends warnings for empty or truncated results into `warnings` list.

## 6. Business Narrative Composition and Faithfulness

Implemented in [`backend/app/workflow/orchestrator.py#L538-L560`](file:///c:/D_drive/AI_FOR_BI_P/backend/app/workflow/orchestrator.py#L538-L560):
- Takes the user question, executed SQL, row count, and the first 10 rows of query results.
- Prompts the LLM via `COMPOSER_PROMPT`:
  - **Constraint:** *"Grounded strictly in the following query results, state the key factual findings and any business caveats. Never claim causation from mere correlation. If results are empty, state that plainly."*
  - **Structure:**
    - **Direct Answer:** Exact numbers from data.
    - **Key Findings:** Bullet points summarizing metrics.
    - **Caveats / Data Coverage:** Data boundaries and limitations.
- Extracts first 3 result observations as structured evidence citations in `key_findings`.
